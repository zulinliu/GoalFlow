# Product

## Register

brand

## Users

GoalFlow serves builders who use AI coding agents to deliver real software features. Primary users are solo developers, open-source maintainers, product-minded engineers, and Chinese or bilingual teams that want an agent to move from a high-level feature goal to a release-ready result without losing design quality, engineering control, or release safety.

## Product Purpose

GoalFlow exists to turn one feature goal into a complete agentic delivery flow: design, prototype, implementation, verification, documentation, git hygiene, PR preparation, and release gates. Success means a user can invoke one skill, get the right mix of Impeccable-led UX/frontend craft and GSD-led engineering workflow, and receive production-oriented output with durable artifacts and explicit safety boundaries.

## Brand Personality

Clear, disciplined, and quietly ambitious. GoalFlow should feel like a precise delivery instrument, not a generic automation bot or a project-management wrapper.

## Anti-references

- Generic DevOps pipeline diagrams with arrows, checkmarks, and indistinct nodes.
- Over-marketed AI productivity language that promises magic without gates.
- Decorative developer-tool dark mode that does not explain the workflow.
- A single checkmark as the entire identity.
- README pages that blur agent-chat invocations and shell commands.

## Design Principles

1. Design leads, engineering follows with traceability.
2. Autonomy moves through gates, not around them.
3. One user goal should produce durable artifacts, not just chat history.
4. Safety and human accountability are part of the brand.
5. Chinese and English users should both understand how to install, invoke, review, and ship.

## Accessibility & Inclusion

Use clear language, explicit command contexts, and bilingual public documentation. Avoid color-only meaning in diagrams and logo usage. Motion or prototype examples must support reduced-motion alternatives when GoalFlow is used to create UI work.
